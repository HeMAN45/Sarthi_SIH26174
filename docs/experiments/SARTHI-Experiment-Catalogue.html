1 · What SARTHI can check

An experiment is a list of steps. Each step asks for evidence the camera can see — an object, what a hand does with it, a body action — and SARTHI judges the steps in order, speaks the next one, alerts on mistakes and writes a timestamped, tamper-evident log.

Honest limits
  • Fingers: thumbs-up, pinch, counting fingers — the pose model has wrists, not fingers.
  • Fine manipulation: twisting a cap one way or the other, cutting, writing.
  • Whether liquid actually flowed — only that the container was tipped while held.
  • Small or flat objects are unreliable with the stock model: books, spoons, pens, pills.
  • Fast movements on a laptop: a quick wave or clap falls between frames.
  • Two objects in one builder step (a procedure file can do it).
  • Telling two similar objects apart (two medicine bottles) — train each one.

2 · Body actions

Read from the skeleton (17 body points) and measured against the body's own axis — shoulders to head, hips to shoulders — never the image, so a crew member upside down raises a hand exactly as one standing does. One-hand actions can be required for the left or the right hand; the other hand raises a spoken wrong hand alert.

Doing it well
  • Sit 60–80 cm from the laptop; chest, both elbows and the table in view.
  • Hold each action about two seconds; do one thing at a time and wait for the voice.
  • Movements slowly and widely: a laptop reads 3–4 frames a second.
  • Hold objects so they fill a good part of the frame for “show it”.
Alerts it speaks
  • Wrong object — picking up what a later step needs.
  • Wrong hand — the other hand doing a left/right step.
  • Out of sequence / skipped — in Strict mode.
  • No progress — a step left undone for 60–120 s.
  • Cannot verify — evidence too weak to trust.

3 · Running and building an experiment

Start In the Clippy folder: uv run python scripts/web_demo.py, then open http://localhost:8000.

Run a built-in one

  1. Procedures tab → Built-in → the experiment's card → Load.
  2. Mission tab → choose Clean (normal) or Strict (also flags steps done early) → New run.
  3. Follow the voice. An alert covers the top of the video: Acknowledge (or Esc).
  4. At the end a debrief appears; End run releases the camera.
  5. Archive tab → the run → steps, alerts, video, Verify chain.

Build your own

  1. Procedures → Build an experiment → type a name.
  2. Add steps from Objects (80 stock + your trained ones, listed first) or Body actions.
  3. In each step choose what is done with the object — Show / Hold / Pour / Move — and which hand — Either / Left / Right.
  4. Leave the wording empty to use the default shown in grey, or type your own.
  5. Save (it appears under Your experiments, even after a restart) or Save & run.

“Put it back in its place” and “two objects in one step” need a procedure file — copy procedures/seed_germination.yaml and edit it.

4 · Teaching SARTHI a new object

  1. Models tab → type the object's name → +. Keep the background class.
  2. Capture from the live laptop camera in the room you will run in: 40–60 photos per object or state (5–6 bursts of ×10, moving it between bursts) — different angles, distances, both hands, standing and held. Background: 60–80 — the empty table, empty hands, a finger, your face, and every other prop on its own.
  3. Train → Objects → Find the object in my photos → check the boxes in Boxes (click a wrong one to leave it out) → 15 epochs → Train object detector (≈15–20 min on a laptop).
  4. Test model live → Deploy. Your object joins the 80 stock ones and stays after a restart; deleting its class hides it again.
Photos or video? A video upload is cut into 40 still frames, so it is a faster way to collect varied photos — record one slow 15–20 s clip per class. Its held-out accuracy looks better than it is (neighbouring frames are near-copies); judge it with Test model. For a pouring step, include photos of the object tipped at 30–90°.

7 · Demo plan (internal hackathon)

  1. The story (30 s). On BAS, ground support cannot watch every experiment live. SARTHI runs on board, offline, and supervises the crew step by step.
  2. Main demo — Seed germination check (Clean). The full five steps with voice prompts; show the debrief.
  3. A mistake — wrong object. New run; at step 2 pick up the phone: “Wrong object: the crew tablet is for step 3. Now: Water the seeds.”
  4. Human activity — Crew fitness check. Raise the LEFT hand at step 1: “Wrong hand: use your right hand.” Then wave, lift the bottle with the right hand, drink.
  5. Out of sequence — Strict mode. Germination again: return the tray before photographing it.
  6. The record. Archive → verify the chain: a few kilobytes of verified log go to the ground, not a video stream.
  7. Close. “A new experiment is a new file” — show this catalogue: space, healthcare, factories.
Before the demo Rehearse twice in the same room and light. Check in the preview that every prop gets a box. Keep one good run's video on disk. Backup demo: Potable water sampling.
